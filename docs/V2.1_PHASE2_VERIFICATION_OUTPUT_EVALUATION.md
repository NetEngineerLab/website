# NetEngineerLab V2.1 Phase2 — Verification Output Parser + Execution Result Evaluation

**Status:** Feature/Core Accepted  
**Scope:** Cisco IOS, Huawei VRP, H3C Comware, Juniper Junos, Arista EOS

## Goal

Close the network-change loop:

`Running Config -> Desired Intent -> Minimal Delta -> MOP -> CLI Verification Output -> Evidence -> PASS / FAIL / ROLLBACK_REQUIRED / INCONCLUSIVE`

## Architecture

- `verification-output/parser.js` parses supported post-check CLI output into vendor-neutral evidence.
- `verification-output/evaluator.js` evaluates evidence against the desired canonical state and rollback contracts.
- `verification-output/engine.js` binds MOP verification checks, CLI output, evidence, and final decision.
- `change-execution/engine.js` exposes `evaluateOutputs(execution, outputs, options)`.

## V1 Managed Evidence

- Aggregate logical state and bundled/active member count
- Logical interface operational state and visible error counters
- Allowed VLAN set and native/PVID VLAN
- Target VLAN inventory presence

Unsupported or incomplete evidence is not treated as success. It returns `INCONCLUSIVE`.

## Decisions

- `PASS`: all required supported evidence proves the desired post-change state.
- `ROLLBACK_REQUIRED`: an explicit rollback trigger is proven, including aggregate down, member count mismatch, trunk semantic mismatch, unexpected member, or new interface errors.
- `FAIL`: a required check fails without a mapped automatic rollback trigger.
- `INCONCLUSIVE`: evidence is missing or cannot prove success/failure safely.

## Safety Rules

1. Fail closed: absence of evidence never becomes PASS.
2. Parser only evaluates the currently managed configuration domains.
3. Raw output is retained with parsed evidence for auditability.
4. Rollback decisions are derived from the same rollback-trigger contracts emitted by the MOP layer.
5. Vendor-specific output parsers normalize into one evaluation model; vendor syntax never leaks into desired-state semantics.

## Contract Test

`npm run test:verification-output-evaluation`

Covers five-vendor PASS, aggregate-down rollback, trunk-semantic rollback, and partial-output INCONCLUSIVE behavior.

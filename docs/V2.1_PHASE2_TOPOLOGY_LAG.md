# NetEngineerLab V2.1 Phase2 — Device Topology + LAG Foundation

Status: Implemented

## Purpose
Upgrade interface identity from a flat string to a topology-aware object:

`Device -> Stack/Virtual-Chassis Member -> Slot -> Line Card -> Physical Port -> Breakout Lane -> Logical Aggregate`

Then bind verified physical members into a canonical LAG intent and render it per vendor.

## Implemented topology layers
- stack / virtual-chassis member range validation
- fixed slot metadata
- explicit modular chassis / line-card inventory resolver
- physical port groups
- breakout parent/child relationship
- fail-closed lane bounds and missing naming rules
- logical aggregate interface model

## Baseline member support
- Cisco C9200L-24T-4G: StackWise member-aware interface naming; member range gate based on Catalyst 9200 stacking support.
- Juniper EX3400-24T: Virtual Chassis member-aware `ge-member/fpc/port` naming; member range gate up to the supported EX3400 VC size.
- Huawei/H3C baseline models: conservative standalone mapping until a model-specific stack/IRF topology profile is verified.
- Arista 7050SX3-48YC8: standalone physical topology plus explicit 100G uplink breakout lane mapping.

## Canonical LAG
Canonical fields:
- aggregate ID
- mode: `lacp | static`
- resolved member interfaces
- optional description

Vendor logical interface mapping:
- Cisco IOS: `Port-channel<N>`
- Huawei VRP: `Eth-Trunk<N>`
- H3C Comware: `Bridge-Aggregation<N>`
- Juniper Junos: `ae<N>`
- Arista EOS: `Port-Channel<N>`

## Safety rules
1. Aggregate members must resolve to real topology interfaces first.
2. At least two unique members are required.
3. Member speed mismatch is rejected.
4. Invalid member, slot, line card, physical port or breakout lane is rejected.
5. Breakout auto-resolution requires an explicit breakout naming rule.
6. Cross-vendor port names are never guessed.
7. Unknown stack/chassis capabilities remain fail-closed.

## Modular chassis support
The core now supports an explicit inventory object containing members, slots, line cards and line-card port groups. This allows future verified device catalogs to plug in modular chassis without changing the resolver contract.

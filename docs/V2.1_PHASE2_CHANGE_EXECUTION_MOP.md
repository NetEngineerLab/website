# NetEngineerLab V2.1 Phase2 — Change Execution / MOP V1

## Goal
Upgrade configuration analysis into an execution-oriented change workflow:

`Running Config -> Canonical State -> Desired Intent -> Minimal Delta -> Risk -> Pre-check -> Execute -> Post-check -> Rollback Gate`

## Components
- `change-execution/risk-score.js`: deterministic 0-100 risk score and band.
- `change-execution/verification.js`: vendor-aware pre/post verification commands and expected conditions.
- `change-execution/runbook.js`: ordered MOP steps with stop conditions and rollback gate.
- `change-execution/engine.js`: composition entry point over Minimal Delta.

## Safety rules
1. Blocked reconciliation is critical risk and cannot produce an execute step.
2. No-op state does not invent configuration commands.
3. Pre-check failure means STOP before change.
4. Rollback is triggered by aggregate-down, member-count mismatch, trunk semantic mismatch, unexpected members, or attributable new interface errors.
5. Risk score is deterministic and explainable through factor contributions.
6. Verification commands are operational aids; an operator must compare output to the listed success criteria.

## V1 managed scope
LAG + trunk VLAN + native/PVID + member bindings + interface description across Cisco IOS, Huawei VRP, H3C Comware, Juniper Junos, and Arista EOS.

# NetEngineerLab V2.1 Phase2 — Change Planning V1

## Goal
Upgrade Intent Composition from direct configuration generation into an auditable network change workflow:

`Desired Intent -> Current/Observed State -> Precheck -> Impact -> Before/After Diff -> Forward Config -> Rollback Config -> Verification Plan`

## Scope
- Canonical change-plan request model
- Current intent snapshot support
- Observed inventory constraints
- Aggregate-ID collision detection
- Existing LAG member conflict detection
- Protected-interface detection
- VLAN-presence validation
- Resource impact summary
- Semantic Before/After diff
- Configuration line diff
- Five-vendor forward plan
- Five-vendor rollback plan
- Ordered execution phases
- Fail-closed plan status (`ready` or `blocked`)

## Design rule
A blocked plan may still expose impacts and conflicts for diagnosis, but must not be treated as execution-ready.

## Forward strategy
For an existing known baseline, V1 deliberately uses a conservative replace strategy: tear down the known current composite state, then apply the desired composite state. This is more disruptive than a future minimal-delta engine, but it is deterministic and avoids leaving stale LAG members or stale trunk state behind.

## Rollback strategy
- New object: tear down the newly created aggregate state.
- Existing known object: tear down the desired state, then restore the full known Before configuration.

Rollback is generated from the same resolved device/vendor/topology model as Forward configuration. It does not guess unknown pre-change state.

## V1 limitations
- Does not ingest arbitrary running-config text as current state yet.
- Does not calculate a minimal command-by-command patch yet.
- Does not perform live device execution.
- Does not auto-create missing VLANs; when observed VLAN inventory is supplied, missing VLANs block the plan by default.
- Rollback correctness depends on the supplied Before state being accurate.

## Next extension
Parser-backed Running Config Snapshot -> State Reconciliation -> Minimal Delta Planner -> Pre/Post Check Commands -> Transaction/Change Set.

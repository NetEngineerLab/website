# NetEngineerLab V2.1 Phase2 — Domain 2: Interface / VLAN Configuration

**Status:** Implemented foundation  
**Version:** V2.1-Phase2-Domain2  
**Date:** 2026-09-05

## Goal

Validate that the Shared Core + Vendor Renderer Foundation is reusable beyond ACL by adding a second independent configuration domain.

## Canonical scope

The first Interface/VLAN domain model intentionally covers the portable Layer-2 switchport subset:

- interface name (vendor-native identifier)
- optional description
- access / trunk mode
- access VLAN
- trunk allowed VLAN set
- trunk native/PVID VLAN

VLAN IDs are restricted to 1–4094. A native/PVID VLAN must also be present in the allowed VLAN set.

## Explicitly out of scope for V1

- automatic cross-vendor physical interface renaming
- hybrid ports
- QinQ / dot1q-tunnel
- private VLAN
- VLAN translation
- voice VLAN
- L3 routed interfaces / SVI
- platform-specific defaults

Automatic interface renaming requires a future Platform Profile because port nomenclature depends on vendor, product family, chassis and interface type.

## Shared architecture

```text
Canonical Config Envelope
        ↓
Interface/VLAN Domain Model
        ↓
Domain Vendor Registry
        ↓
UNCHANGED Shared Renderer Engine
        ↓
Cisco IOS / Huawei VRP / H3C Comware / Juniper Junos / Arista EOS
        ↓
Generated CLI
        ↓
Domain Parser
        ↓
Canonical Model
        ↓
Semantic Round Trip
```

ACL and Interface/VLAN keep separate domain registries/parsers/renderers while reusing the same shared vendor registry contract and renderer orchestration.

# NetEngineerLab V2.1 Workflow UI Production Fix — AUDIT_2

**Audit role:** 2号审计员  
**Date:** 2026-09-06  
**Scope:** 22 active tools × EN/zh-CN = 44 production tool pages  
**Decision:** PASS / ACCEPTED

## 1. 审计目标

确认全站统一保留新版 Engineering Workflow，不退回旧版 Related Tools，并验证截图所示“新版 HTML 退化为连续文本”的生产风险已从架构上消除。

## 2. 第一轮审计发现

第一轮不是直接通过。审计发现 8 个页面仍残留旧版 Related Tools 独立模块：

- Bandwidth & Transfer Time Calculator — EN / zh-CN
- -48V Telecom Battery Runtime Calculator — EN / zh-CN
- IPv6 & NAT Capacity Planner — EN / zh-CN
- Wi-Fi Coverage & Capacity Planner — EN / zh-CN

根因是旧清理逻辑只识别 `id="related"`，而上述旧模板没有该 ID。

**审计结论：第一轮 FAIL，要求返工。**

## 3. 返工结果

返工后：

- 旧 Related Tools 独立区块：0
- 新版 Workflow 区块：44/44
- 每页 Workflow 区块数量：1
- Tool Registry active tools：22
- Workflow Registry：6
- Workflow 覆盖：22/22

Bandwidth 与 Optical Power Budget 现在使用同一新版结构：

1. ENGINEERING WORKFLOW
2. Current workflow
3. Step X of Y + progress
4. Previous / Next
5. Related tools
6. 仅存在第二工作流时显示 Also used in / 同时用于

## 4. CSS / 生产缓存风险审计

原 Workflow 样式依赖通用 `tool-design-system.css` 尾部规则。生产端曾出现新版 HTML 与旧缓存 CSS 组合，导致卡片退化为普通连续文本。

已新增独立：

`website/assets/css/tool-workflow.css`

并由构建脚本按内容哈希统一注入：

`/assets/css/tool-workflow.css?v=66c8998b2681`

审计结果：

- 44/44 页面均且仅引用 1 次 Workflow 专用 CSS
- 44/44 页面引用当前内容哈希
- CSS 包含 context / nav / card / related / progress / chip 完整规则
- 专用 CSS 已进入 shared runtime / Service Worker 构建体系
- 新增 `audit:workflow-ui`，以后缓存哈希或 UI 结构漂移会直接阻断 `prepare:launch`

## 5. UI 信息层级审计

本次同时去掉了无价值重复：

- Related Tools 外层已有标题，卡片内部不再重复显示 `Related tools`
- 主 Workflow 不再重复出现在 Membership 中
- `Workflow membership` 改为仅在存在第二工作流时显示 `Also used in`
- Related Tools 桌面端最多三列，平板两列，手机单列

审计认为新版信息层级优于旧版，且保留了旧版简洁性的优点。

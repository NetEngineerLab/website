EVPN Sebuah Kegagalan CE Ping: MTU Ulasan Kasus

Tinjau insiden EVPN sintetis: mengapa rute sehat bertopeng paket a1550- byte overlay melebihi a1500- byte underlay IP menyesalkan MTU.

Skenario pendidikan sintetis. Tidak ada akses perangkat hidup, menangkap pelanggan atau reproduksi insiden Ciname. Retrospektif statis ini tidak memiliki keadaan sesi; gunakan laboratorium terpisah untuk praktek interaktif.

Diulang: 2026-10-16

Dampak dan scope

Sebuah tim operasi bisa salah membaca yang sehat EVPN dashboard sebagai bukti bahwa layanan jembatan bekerja. Dalam kasus ini ditemukan, kecil keepalives berhasil sementara penuh ukuran CE echo tes gagal kedua cara. Layanan yang terkena adalah jembatan IPv4 L2; IPv6 dan diarahkan gerbang berada di luar bukti.

Catatan investigasi

  1. Sinyal stabil: sesi, rute titik akhir yang diimpor dan penerusan MAC terinstal semua cocok dengan layanan yang dimaksudkan.
  2. Akses VLAN, terowongan VNI dan keanggotaan jembatan setuju; resolusi tetangga langsung dan gema kecil mengesampingkan isolasi total titik akhir.
  3. Ukuran menyapu terisolasi batas: 1422-byte muatan lewat, 1423 gagal. Sebuah egress berkorelasi MTU-drop peningkatan terikat kerugian ke underlay yang dibatasi daripada spekulasi BGP restart.

Aritmetik akar dan penyebab

Jalur model IP MTU was 1500, tetapi a1472-byte muatan ICMP menciptakan paket IP dalam diri dan a1550- byte paket IP luar. Bagian luar DF dan jalan keluar eksplisit adalah bagian dari perbaikan ini. Extra-50 bytes meliputi 14- byte header dalam Ethernet plus 20- byte luar IPv4, 8- byte UDP dan 8- byte VXLAN. Ethernet / FCS tidak dihitung terhadap IP MTU. Tidak ada tag, pilihan IP atau terowongan tambahan yang hadir.

Kontrol perbaikan dan verifikasi

Sebelum perubahan nyata, pastikan lengkap relevan underlay path, kedua arah, alternatif ECMP dan platform konvensi MTU. Posting pendidikan - perubahan profil menggunakan 1600- byte jalur IP MTU: semua empat ukuran probe kemudian melewati kedua cara, jumlah oversize- drop berhenti tumbuh, tidak ada pecahan baru muncul dan EVPN tetap didirikan. Ini adalah bukti simulasi, bukan konfigurasi yang dieksekusi atau resep universal a1600- byte. Mengurangi layanan batin MTU adalah pilihan lain dengan konsekuensi aplikasi dan titik akhir.

Pelajaran untuk catatan kejadian

Rekam amplop paket, uji arah dan counter jendela dengan setiap kesimpulan. Pisahkan probe kecil yang terjangkau dari transportasi yang memadai MTU. RFC7348 memungkinkan router menengah untuk fragmen secara umum; perilaku DF / drop di sini adalah kondisi yang dideklarasikan, bukan aturan selimut.

Mengapa ping kecil berhasil?

Panjang IP terlampir mereka sesuai dengan model MTU terbawah; probe full- ukuran melebihi itu.

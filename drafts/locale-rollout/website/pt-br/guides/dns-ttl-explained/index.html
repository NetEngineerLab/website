Um DNS TTL é um time-to-live em um conjunto de registro de recursos. A unidade na mensagem DNS é segundos. Uma calculadora TTL, ou calculadora DNS TTL, está apenas fazendo bico de conversão de unidade mais qualquer entrada de cache-idade que você adicionar. A conversão em si é exata. O momento em que um registro alterado se torna visível não é.

O que os segundos contam

RFC 1035 define o TTL como um inteiro de 32 bits não assinado contado em segundos. Um valor de zero significa que a resposta não está em cache além da transação atual. Nada nessa definição diz que um TTL de 300 segundos, um TTL de 600 segundos ou um TTL de 86400 segundos irá atualizar cada resolução de uma vez.

TTL para minutos e TTL para segundos

TTL para minutos é segundos divididos por 60. TTL para segundos é minutos multiplicados por 60, ou horas multiplicadas por 3600. Ambas as direções são aritméticas inteiras para os cinco valores abaixo, então cada linha pode ser verificada sem arredondamento.

300, 600, 3600, 14400 e 86400 segundos

Um 300 TTL em minutos é 300 / 60 = 5 minutos, que é 1/12 de uma hora. Um 600 TTL em minutos é 600 / 60 = 10 minutos, que é 1/6 de uma hora. 3600 / 60 = 60 minutos = 1 hora. 14400 / 60 = 240 minutos = 4 horas. Um TTL 86400 em minutos é 86400 / 60 = 1440 minutos = 24 horas. A verificação reversa é a última coluna: 5 x 60 = 300, 10 x 60 = 600, 60 x 60 = 3600, 240 x 60 = 14400 e 1440 x 60 = 86400.

Operadores digitam esses valores antes de uma migração ou em uma zona que deve mudar lentamente. Eles são exemplos da aritmética, não um programa de propagação recomendado e não um padrão de RFC 1035.

Um cache não é a rede

O restante do TTL é local para o solucionador que guardou a resposta. Tome um registro A cujo autoritário TTL é 3600 segundos, e três solucionadores, como exemplo apenas:

  1. A Resolução A guardou-o há 600 segundos. TTL restante = 3600 - 600 = 3000 segundos = 50 SAP.
  2. A Resolução B guardou-o agora. TTL restante = 3600 - 0 = 3600 segundos = 60 minutos.
  3. O ainda tem a resposta anterior, que em cache quando o TTL foi 86400 segundos, e 3600 segundos passaram lá. TTL restante = 86400 - 3600 = 82800 segundos = 23 horas hereditário.

Esses três relógios não são uma vez de propagação. O TTL antigo ainda governa qualquer cache que tenha armazenado o registro anterior. Um registro diferente com o mesmo nome, como um MX com um TTL 3600 segundos ao lado de um A com um TTL 300 segundos, expira em seu próprio relógio.

O cache negativo é um temporizador separado. RFC 2308 define o TTL de uma resposta NXDOMAIN ou NODATA para o menor do campo MÍNIMO SOA e próprio registro SOA TTL. Se uma zona mostra um registro SOA TTL de 600 segundos e um MÍNIMO de 3600 segundos, a resposta negativa usa 600 segundos, que é de 10 minutos. Se a zona mostrar diferentes campos SOA, o resultado é diferente. Que 10 minutos não se aplica a um registro A positivo, e não é um intervalo fixo para cada zona.

Mudar o recorde não é esperar um TTL

Publicar uma nova resposta nos servidores autoritários não reescrever caches recursivos. Cada cache mantém o conjunto armazenado até que o TTL remanescente da entrada atinja têxteis zero, a menos que a própria política do resolvedor faça outra coisa. Alguns resolvedores fecham o TTL que mantêm. RFC 8767 permite servir uma resposta fraca quando o solucionador não pode atualizá-la dos servidores autorizados. Mudanças na delegação, validação do DNSSEC e caches de clientes ou aplicativos podem mover o tempo que um usuário vê os novos dados também.

Baixando o TTL antes de uma mudança afeta somente caches que armazenam o registro após o menor valor ser visível nos servidores autorizados. Caches que já armazenavam o TTL antigo mais longo mantêm esse valor mais longo até que seu próprio restante se esgote. Não leia "o TTL expirou" como "a rede está agora em sincronia".

Perguntas mais frequentes

O que é um DNS TTL?

RFC 1035 define um TTL de registro de recursos como uma contagem de 32 bits de segundos. Limita quanto tempo um solucionador pode reutilizar o conjunto de registro armazenado. Não é um relógio para sincronização DNS mundial.

Quantos minutos é um 300 segundos DNS TTL?

300 dividido por 60 é de 5 minutos. O mesmo passo dá 10 minutos para 600 segundos, 60 minutos para 3600 segundos, 240 minutos para 14400 segundos e 1440 minutos para 86400 segundos.

Como converter um TTL em minutos de volta para segundos?

Multiplique os minutos por 60. Cinco minutos são 300 segundos, dez minutos são 600 segundos, 60 minutos são 3600 segundos, 240 minutos são 14400 segundos e 1440 minutos são 86400 segundos.

A expiração do TTL significa que cada solucionador tem o novo recorde?

Não. Cada cache recursiva mantém seu próprio TTL restante. Um solucionador que ainda tenha uma resposta 86400 segundos mais antiga pode devolvê-la após um solucionador que guardou uma resposta de 300 segundos ter expirado. RFC 8767 também permite uma resposta fraca quando uma atualização falha.

O TTL restante é o mesmo número do TTL antigo?

Apenas para uma entrada de cache que foi armazenada. O restante do TTL é que a entrada é armazenada TTL menos o tempo já decorrido naquele resolvedor. Um registro MX ao lado de um registro A carrega seu próprio TTL.

O cashmemes negativos têm o endereço-regme TTL? guindastes?

Não por padrão. RFC 2308 recebe a resposta negativa TTL do menor do campo MÍNIMO SOA e do registro SOA TTL. Esses campos vêm da zona que você consulta. Eles não são o registro A positivo TTL.

REDE DE CÂMARA

Como avaliar o rendimento de dados da câmera IP PoE

Adicione apenas os fluxos que usam o mesmo link ao mesmo tempo. Largura de banda da rede da câmera, em Mbit/s, é essa soma vezes uma mesada que você anota. Um orçamento de energia do interruptor PoE é um cálculo separado em watts.

Largura de banda para câmeras IP é o vídeo codificado que realmente atravessa o link que você está dimensionando, além de uma margem declarada para cabeçalhos e curtos surtos. A potência PoE não define esse número. Os números trabalhados abaixo são exemplos de cenários. Eles não são uma taxa de bits de câmera universal.

1. Fórmula de largura de banda

Para um caminho, em megabits por segundo:

Path payload (Mbit/s) = 中 fluxos simultâneos nesse caminho
Quando cada câmera contribui com os mesmos fluxos: carga útil = contagem de câmera × (soma das taxas de fluxo por câmera)
Carga de planeamento = carga útil × sobrecarga

Unidades: cada taxa de fluxo é a taxa de bits codificada média em Mbit/s (megalinhas por segundo, decimais). Contagem de câmeras é uma contagem de câmeras cujos fluxos usam este caminho durante a mesma hora ocupada. O subsídio é adimensional. O caso trabalhado deste guia utiliza 1.15. Esse fator é uma suposição de planejamento para cabeçalhos de protocolo e picos curtos. Não é um requisito IEEE 802.3.

Se a taxa de bits que você digita já foi medida na porta de swear, ela já pode incluir cabeçalhos Ethernet, IP, UDP e RTP. Não multiplique essa medida por 1.15 novamente. Se o número é a configuração de vídeo codificada da câmera, os cabeçalhos ainda estão fora dele, e uma mesada pertence ao plano.

Mantenha a taxa média de registro e o pico curto separados. O armazenamento segue a média dos fluxos que são registrados. O uplink também deve sobreviver ao pico de horas ocupadas que você projeta.

2. A contagem da câmera vezes uma taxa de fluxo

Usar contagem × taxa apenas quando cada câmera adiciona essa taxa ao mesmo caminho. Um total do site não é a ligação ascendente de um interruptor de acesso a menos que cada câmara tenha casas nesse interruptor.

3. H.264 e H.265

H.264 e H.265 são diferentes padrões de codificação de vídeo. ITU-T H.264 especifica codificação avançada de vídeo. ITU-T H.265 especifica codificação de vídeo de alta eficiência. Um codec posterior pode usar menos bits para uma imagem semelhante em algumas cenas. A diferença não é uma percentagem de poupança fixa.

Não aplicar uma percentagem de poupança fixa quando você alterar codecs. Movimento de cena, comprimento do GOP, controle de taxa de bits e o perfil do fornecedor todos movem o Identidade. O artigo branco da Axis sobre controle de taxa de bits diz que fluxos de taxa de bits variáveis crescem quando a cena fica ocupada, e ele não publica um por cento que se encaixa em cada câmera. Digite a taxa de bits média do perfil que você irá realmente gravar e visualizar.

O Planner de Rede de Câmeras IP ainda neste site estima por câmera Mbit/s como megapixels × um coeficiente codec × (quadros por segundo 15) × 8. Os coeficientes nessa página são 0,075 para H.264, 0,045 para H.265 e 0,24 para MJPEG. Esses coeficientes são um modelo interno de primeira passagem. Eles não são uma câmera medida, e o intervalo entre 0,075 e 0,045 não deve ser reutilizado como uma porcentagem de poupança H.265. Substitua a estimativa pela taxa de bits configurada ou medida antes de uma decisão de projeto. Este guia não muda esse planejador.

4. Fluxo principal, sub fluxo e a taxa real

Muitas câmeras publicam um stream principal para gravação e um sub stream para visualização ao vivo. Adicione um fluxo somente se estiver habilitado e usar o caminho que você está dimensionando, ao mesmo tempo que os outros.

  • Exemplo de fluxo principal, refeitório gravado para um NVR a montante do switch de acesso: média de 4,0 Mbit/s, unicast.
  • Exemplo de sub-pasta, visto por um PC operador que também está a montante do mesmo switch: média de 0,5 Mbit/s, unicast, concorrente com o fluxo principal.
  • Por câmera nesse uplink: 4.0 + 0.5 = 4,5 Mbit/s. Isto ainda é um exemplo, não uma planilha de dados.

Se o PC operador estiver no mesmo switch de acesso, o sub fluxo não usa o uplink. A carga útil do uplink é então contagem da câmera × 4,0 Mbit/s somente. Não adicione o sub- fluxo nesse caso.

Não conte o mesmo fluxo principal duas vezes. O link de acesso carrega-o uma vez. Um link de agregação carrega a soma dos uplinks de acesso que o alimentam, que é os mesmos fluxos uma vez, não novamente no topo.

Gravar o armazenamento usa os fluxos que o gravador armazena. Neste exemplo que é o fluxo principal de 4,0 Mbit/s, não o fluxo sub de 0,5 Mbit/s, a menos que você também grave o fluxo sub. Os cabeçalhos de rede não são adicionados a essa linha de armazenamento, a menos que o gravador os guarde.

5. Alternar uplink

Tamanho de cada link de acesso para as câmeras naquele interruptor, não para todo o Mirror. Carga de planeamento = carga útil × sobrecarga. O subsídio de trabalho deste guia é × 1.15. Uma margem de crescimento é um segundo fator. O caso trabalhado utiliza × 1,20 após o fator de sobrecarga. Escreva ambos para que não sejam aplicados duas vezes a um número que já os inclui.

O IP Camera Network Planner aplica o seu próprio × 1,20 para o total codificado estimado e etiqueta o resultado como largura de banda, incluindo 20% headroom protocolo. Em seguida, procura o menor link no conjunto 1, 10, 25, 40 ou 100 Gbit/s cuja capacidade é pelo menos o dobrolhas desse total, e relata a capacidade remanescente como Mbit/s desse link menos o total. Isso é um esboço de ligação dupla dentro do planejador. Não prova que os dois links são independentes e não utiliza o fator × 1,15 deste guia. Não multiplique um resultado planejador por 1.15 novamente.

6. Remuneração e margem

N-1 significa que um componente nomeado pode falhar e o serviço ainda atende ao alvo que você escreveu. Para o uplink, o caminho sobrevivente deve carregar a carga que se move para ele. Um único uplink não tem nenhum caminho sobrevivente. Dois links de 1 Gbit/s atendem a uma verificação de largura de banda N-1 somente quando qualquer link pode carregar a carga de planejamento por si só, e apenas para largura de banda. Controle de pilha, fontes de alimentação e o NVR são domínios de falha separados.

Manter as licenças separadas:

  • Protocolo e subsídio de rotura sobre dados: × 1.15 no exemplo deste guia, ou do planejador × 1.20 na sua própria estimativa. Não no mesmo número.
  • Subsídio de crescimento sobre os dados: × 1,20 no caso trabalhado, aplicado após sobrecarga. Esta é uma escolha de projeto, não um padrão.
  • PoE watt headroom, abaixo, é um por cento em watts. Não altera Mbit/s.

7. PoE poder não é largura de banda de dados

IEEE 802.3 define como uma porta de fornecimento de energia fornece energia DC para um dispositivo alimentado. Não define a taxa de bits de vídeo da câmera. Um interruptor pode passar o orçamento de watts e ainda falhar tensão remota, ou passar tensão e ainda congestionar o uplink.

A calculadora de orçamento de energia PoE, que esta página não modifica, usa:

Watts de origem por dispositivo = watts de PD
Orçamento necessário de comutação = watts fonte × contagem do dispositivo × (1 navegador + fração)

Fração de perda de cabo e fração de headroom são os por cento que você entra, dividido por 100. A calculadora também requer contagem de dispositivo ≤ PoE port count, e PD watts ≤ o limite de classe codificado para o padrão selecionado: 12.95 W (802.3af), 25.5 W (802.3at), 51 W (802.3bt Tipo 3) ou 71.3 W (802.3bt Tipo 4). São os watts do dispositivo. Os poderes de classe PSE correspondentes na mesma calculadora são 15.4 W, 30 W, 60 W e 90 W. Os resumos públicos do IEEE 802.3 listahan os mesmos pares. O percentual de perda é uma entrada de planejamento, não uma simulação completa do canal.

O Planner de Rede de Câmeras IP usa uma linha de watts diferente: contagem de câmeras × watts inseridos × 1,25. Esse único fator de 25% não é o mesmo que perda e headroom inserido separadamente. Não misture os dois resultados.

A tensão remota é um terceiro modelo, na calculadora de queda de tensão PoE. Ele começa a partir da resistência ao condutor para o AWG selecionado a 20 °C, escala-o em 0.00393 por °C longe de 20 °C, constrói a resistência ao loop como dois condutores × comprimento pares, adiciona a resistência de contato que você entra, em seguida, resolve a corrente para a potência de carga e a eficiência de entrega que você entra. Um orçamento de watts que passa não responde a essa tensão.

8. Exemplo: 16 câmeras, um interruptor de acesso

Exemplo, não uma folha de dados da câmera. Dezasseis câmaras fixas. Cada um envia um fluxo principal unicast de 4,0 Mbit/s para um NVR a montante deste switch, e umregamento unicast de 0,5 Mbit/s para um PC operador que também está a montante. Ambos os fluxos são simultâneos. O áudio não está incluído. Nenhum outro tráfego está no uplink.

  1. Carga útil = 16 × (4,0 + 0,5) = 72,0 Mbit/s.
  2. Subsídio adicional × 1,15, assunção deste guia: 72,0 × 1,15 = 82,8 Mbit/s.
  3. zeleira × 1,20 depois disso, também uma suposição: 82,8 × 1,20 = 99,36 Mbit/s.
  4. Um único link de 1 Gbit/ Factor é nominalmente 1000 Mbit/S, então a aritmética se encaixa no estado normal. N-1 não faz: não há segunda ligação. Dois links independentes de 1 Gbit/s precisariam carregar 99,36 Mbit/s depois de um falhar. Essa verificação é apenas a aritmética de largura de banda.

Se o PC operador estiver neste mesmo interruptor, solte o fluxo de sub do uplink: 16 × 4,0 = 64,0 Mbit/s, então 64,0 × Amazon = 73,6 Mbit/s, então 73,6 × 1,20 = 88,32 Mbit/s. Não relate 99,36 Mbit/s para esse caminho.

Armazenamento do fluxo principal gravado apenas,glies decimais (1000, not 1024): gigabytes diários por câmera = 4,0 × 86.400 □ 8 □ 1.000 = 43,2 GB/dia. Dezesseis câmaras: 691.2 GB/dia. Trinta dias: 20.736 GB = 20.736 TB. Esta linha não inclui o sub fluxo 0,5 Mbit/s, RAID, ou a margem de rede × 1.15. Cem câmeras com o mesmo fluxo único de 4,0 Mbit/s, sem registro de subfluxo, são 4,32 TB/dia e 129,6 TB em 30 dias.

Poder para as mesmas dezesseis câmeras, ainda separados da taxa de bits. Digite 12 W no dispositivo alimentado, 15% de perda de cabo, 20% de headroom, e 802.3at na calculadora de orçamento de energia PoE: watts fonte = 12 0,85 = 14.1176 W; orçamento exigido = 14.1176 × 16 × 1.20 = 271.06 W. As mesmas entradas para 24 câmeras requerem 406.59 W. Um interruptor 370 W passa 16 câmeras e falha 24 em watts. Nenhum dos resultados altera os 72,0 Mbit/s.

Tensão é outro conjunto de entrada,PG não esta câmera 12 W. O exemplo de 90 m publicado na calculadora de tensão usa 25,5 W, 48 V fonte, 90 m, dois pares, 45 °C, 0,3 ohm resistência de contato, 90% eficiência de entrega e um piso entrado de 42,5 V. Com essas entradas a calculadora retorna 37,87 V na extremidade distante em 26 AWG (10,13 V casais, abaixo do chão) e 43,51 V em 23 AWG (4,49 V gota, acima do chão). Suíte de dispositivo elétrico da Cláusula 33 da UNH-IOL, citando IEEE Std 802.3-2012 A Tabela 33-18 descreve um intervalo de entrada Tipo 2 de 42,5 V a 57 V e um intervalo Tipo 1 de 37 V a 57 V. O piso 42.5 V nesse exemplo é o limite inferior Tipo 2 usado como uma verificação inserida. Não é uma certificação de um cabo, e um dispositivo tipo 1 pode usar um piso inferior.

Planner cross-check, padrão nessa página, não este exemplo de 16 câmeras: 2 megapixels, coeficiente H.265 0.045, 15 quadros por segundo, 100 câmeras, 15 W, 30 dias. Por câmera = 2 × 0,045 × (15 □ 15) × 8 = 0,72 Mbit/s. Total após o plannerbano × 1,20 = 86,4 Mbit 118. Linha Watt = 100 × 15 × 1,25 = 1875 W. Armazenamento bruto = 86,4 × 30 × 0,0108 = 27,9936 TB, mostrado como 27,99 TB. A linha rotulada utilizável é que a figura 0.85. Um terabyte decimal por dia a 1 Mbit/s é de 0,0108 TB, porque 1 Mbit/s × 86.400 s10 bytes. O planejador dobra seu subsídio de 20% de rede nessa linha terabyte. Não trate 0, 72 Mbit/ s como o exemplo de 4, 0 Mbit/ s acima.

10. Erros comuns e o que verificar

  • Usando o rótulo de resolução como taxa de bits. Leia o perfil ou meça a porta.
  • Subtraindo um percentual fixo para transformar H.264 em H.265. Digite a taxa que você executará.
  • Adicionando um fluxo de sub que permanece no interruptor de acesso, ou omitindo um que sai no uplink.
  • Contando o mesmo fluxo no uplink de acesso e novamente como tráfego extra no link de agregação.
  • Aplicando × 1,15 a uma medição de porta de comutação que já inclui cabeçalhos, ou aplicando tanto 1.15 quanto o 1.20 do planejador.
  • Usando o pico para uma estimativa de disco de 30 dias, ou a média da noite para o uplink ocupado-hora, sem dizer qual.
  • Tratando um passe de watt PoE como prova de tensão remota ounis Mbit/s da câmera.
  • Chamada N-1 passou quando o interruptor tem apenas uma ligação ascendente.

Quando a imagem para ou o link estiver ocupado, meça a média de uma câmera ecategory pique em sua porta de comutação e lista quais fluxos estão habilitados e para onde eles vão. Compare essa soma com o contador uplink. Se as câmeras reiniciarem quando o infravermelho ligar, verifique watts de dispositivo e tensão de ponta, não a taxa de bits.

Limites

Este é um método de planeamento. Não é uma certificação de cabo, um teste de conformidade de codec, ou um substituto para a folha de dados da câmera. Multicast que é corretamente podado não adiciona uma cópia por visualizador; unicast faz. Confirme qual deles você vai implantar. RAID, sobrecarga do sistema de arquivos e gravação pré-evento são armazenamento extra, não incluído na linha de 20.736 TB.

Perguntas mais frequentes

A resolução sozinho pode prever largura de banda para câmeras IP?

Não. Codec, taxa de quadros, movimento de cena e a configuração bitrate alterar o resultado. Utilizar a medida ou a medida de uma única vez de uma única vez.

Uma calculadora de orçamento de energiaproprietário PoE dá largura de banda da rede da câmera?

Não. A calculadora de orçamento de energia PoE beneficiários retorna watts, port count e um limite de classe. Largura de banda da rede da câmera é uma soma separada de bitrates de fluxo simultâneo em Mbit/s.

Posso subtrair uma porcentagem fixa ao mover de H.264 para H.265?

Não. Não aplicar uma percentagem de poupança fixa. H.264 e H.265 são padrões diferentes, e a taxa de bits ainda depende da cena e das configurações do codificador.

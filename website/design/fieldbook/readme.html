一、设计理念

Fieldbook（工程手记）：像一位资深工程师的笔记本。暖白纸面配石墨黑字，只用一种「信号橙」做强调。计算结果放在深色的「仪表读数」面板里。标题偶尔用一句斜体衬线点睛，所有数字都用等宽字体。参考 Linear 的克制、Vercel 的黑白对比、Raycast 的 ⌘K 命令面板，以及 Stripe 的「把公式摆出来」，给人的感觉是：这是一个认真、可信的工程产品，而不是模板站。

    重要更正：v1 的数字算错了。 我对照了真实计算代码 website/tools/optical-power-budget/js/engine.js，并用 Node 实际运行过。代码里：

  • 设计损耗 = 物理损耗 + 工程余量
  • 光通道代价从预算一侧扣掉：等级预算 = 最小发光 − 灵敏度 − 代价

    • 所以 GPON C+ 默认值的正确结果是：设计损耗 28.80（v1 错写成 29.80），剩余 3.20 dB（v1 错写成 2.20），预算占用 90%（v1 错写成 93%）。首页公式区也一起改了。

    另外，线上页面的方法说明和 FAQ 写的是"设计损耗 29.8 dB、高于 B+ 的 28 dB"。那是把代价放在损耗一侧，再和 33 dB 原始窗口比较，剩余同样是 3.2 dB，但和代码的口径不一致。建议以后统一文案（这次没改线上）。

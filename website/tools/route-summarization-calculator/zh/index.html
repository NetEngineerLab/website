        限制
        • 汇总按地址是否相邻，不看现网是否真有这些路由。
        • 收成更短的前缀会盖住中间没有列出的地址。发布前要确认这些地址不该被这条汇总带出去。
        • IPv4 和 IPv6 分开汇总，不会合成一条。
        • 最短前缀长度用来停住继续向上汇总。它不是路由器上的自动命令。

        汇总原理

        路由汇总是把多条更长的前缀收成更少、更短的前缀。路由表和对外通告因此少几条。能不能收，看的是地址是否落在同一个上一级网络里，不是网段名字是否接近。

        1. 每条前缀先归一到网络地址。10.0.0.5/24 写成 10.0.0.0/24。
        2. 已经被更短前缀盖住的条目不再单独通告。有 10.0.0.0/24 时，10.0.0.0/25 是重复。
        3. 剩下的前缀如果长度相同，并且是同一个上一级网络里的一对，就收成那条更短的前缀。10.0.0.0/24 和 10.0.1.0/24 收成 10.0.0.0/23。
        4. 这一步重复，直到不能再收。能收成一条，结果就只有这一条。10.0.1.0/24 和 10.0.2.0/24 不是一对，不能收成一条，结果仍是多条。
        5. IPv4 和 IPv6 分开汇总，不会合成一条。

        更短的前缀会盖住中间没有列出的地址。发布前要确认这些地址不该被这条汇总带出去。

        问答

        两条 /24 一定能收成 /23 吗？

        只有它们是同一个 /23 里的一对。10.0.1.0/24 和 10.0.2.0/24 不是一对，不能收成 10.0.0.0/22。

        结果能直接写进路由协议吗？

        不能。结果只比较地址块。是否通告、是否保留更长前缀的例外，仍要对照拓扑和设备资料。

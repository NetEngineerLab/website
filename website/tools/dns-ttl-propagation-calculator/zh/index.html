DNS TTL变更与传播时间规划

估算逻辑

旧缓存剩余时间等于当前TTL减去已缓存时间，最低为零。典型值是“剩余时间的一半加权威更新延迟”的规划经验值；保守窗口取旧缓存剩余与否定缓存TTL的较大值，再叠加权威更新延迟。

Conservative window = max(Old TTL − Cache age, Negative TTL, 0) + Authoritative update delay

安全的DNS迁移流程

应提前降低TTL，让按旧值缓存的记录先到期；直接查询每台权威DNS确认新TTL；执行记录变更后，通过多个递归解析器持续观察。新服务稳定且不再需要回滚后，再恢复日常TTL。

TTL与查询负载的取舍

当TTL大于零时，每日刷新次数是“持续有人查询同一名称”时每个解析器的理论值，即86400除以TTL。RFC 1035规定TTL为零时记录不能在当前事务之后缓存；此时本工具用每秒刷新一次（每日86400次）作为建模上限，实际流量取决于查询率。低TTL有利于快速变更，但可能提高权威DNS流量。

估算的工程边界

TTL规定DNS资源记录通常可以缓存多久，并不是全球同步倒计时。解析器TTL限制、客户端或应用缓存、委派变更、DNSSEC、权威服务器不可达及serve-stale机制都可能改变用户看到新记录的时间。

DNS标准与依据

正向与否定缓存

RFC 1035定义以秒为单位的资源记录TTL。RFC 2308使用SOA信息定义NXDOMAIN与NODATA否定缓存。

运行例外与服务规模

RFC 8767允许在权威刷新失败时提供过期数据。RFC 9199说明TTL选择会影响缓存时长、时延、韧性和权威服务器流量。

常见问题

DNS记录修改后会立即全球生效吗？

权威DNS可以很快返回新记录，但递归解析器仍可能返回尚未过期的旧缓存。旧TTL以及各缓存条目的已缓存时间会影响客户端看到新记录的时刻。

DNS迁移前应该提前多久降低TTL？

应让按旧TTL缓存的记录在计划变更前有足够时间到期，至少预留一个旧TTL周期，并增加运维余量，同时在所有权威DNS上确认低TTL已经生效。

什么是否定DNS缓存？

解析器可以缓存NXDOMAIN或NODATA响应。RFC 2308规定否定响应TTL取SOA MINIMUM字段与SOA记录TTL的较小值，因此新建域名可能要等否定缓存到期后才能访问。

TTL到期后解析器还能返回旧DNS数据吗？

在特殊故障条件下可以。RFC 8767允许解析器在无法从权威服务器刷新时提供过期数据，因此仅凭TTL不能保证精确的全球切换时间。

这个计算器能保证全球DNS传播时间吗？

不能。工具给出规划窗口；解析器策略、缓存年龄、客户端与应用缓存、权威DNS可用性、DNSSEC、委派变更和运维延迟都会影响实际时间。

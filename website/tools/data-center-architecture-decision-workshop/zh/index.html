5. 理由与迁移审查

为什么不选VXLAN？

如果应用接受路由边界且不需要覆盖分段，VXLAN会增加VTEP、VNI、MTU和控制平面工作，却没有明确需求支撑。先记录缺少的能力，再论证新增层次；偏好评分不能证明成本收益。

S-JUNIPER-EVPN

何时简单三层足够

当应用接受子网边界且不要求跨机架二层业务时，路由Fabric可以作为候选。须验证地址、ECMP行为、故障路径和真实链路容量；此处数量不能验证这些工程属性。

S-RFC7938

何时EVPN带来价值

必要的覆盖分段或Fabric内二层延伸可以构成评估EVPN/VXLAN的理由。须验证业务到VNI/VRF映射、路由支持、MTU与跨厂商行为。正评分不是具体平台满足需求的证据。

S-JUNIPER-EVPN

何时控制器Fabric复杂度值得引入

当一致的策略协调与生命周期治理具有价值，且团队能运维所选模型时，可评估控制器Fabric。ACI只是特定厂商示例。选择前比较许可、API、恢复、生态耦合与培训，不假设所有控制器Fabric行为相同。

S-CISCO-ACI

迁移注意事项

迁移难度保持“未评估”：未收集现有拓扑、维护窗口与应用依赖。盘点网关、地址和策略，测试共存、故障恢复与回退。扩大范围前，制定具有可测验收条件和运维负责人的试点。

S-LOCAL-RUBRIC

常见问题

高分能证明容量吗？

不能。数量计零分，不验证链路、转发表、许可或拓扑。

为何迁移难度未评估？

未收集现有架构、维护窗口及应用依赖。请审查各候选的迁移注意事项。

来源与方法

FitScore = 十项0–4评分之和 / 40 × 100。各权重为1。S-LOCAL-RUBRIC是本地编辑评分；一手文献仅支持架构原理。

  • RFC 7938 — Use of BGP for Routing in Large-Scale Data Centers

    第3–4节讨论传统与Clos设计，以及将二层域限制于边缘的纯三层网络。这是经验性信息文档，不是通用规模门槛。

  • Juniper — EVPN with VXLAN Data Plane Encapsulation

    EVPN提供控制平面学习，VXLAN在IP网络上承载二层覆盖。覆盖分段可服务多租户和必要的二层连接；具体平台能力仍须核实。

  • Cisco Application Centric Infrastructure Design Guide

    ACI展示控制器协调策略及租户、VRF、桥接域模型。这是特定厂商的示例，不代表所有控制器Fabric。须单独核实控制器生命周期、策略依赖和许可。

VLAN与IPv4容量规划方法

计算逻辑

规划器先汇总用户、每用户附加设备和基础设施终端，再叠加扩容余量；然后按每VLAN目标主机数计算所需VLAN数量，并选择能够容纳计算所得每VLAN实际需求的最小常规IPv4前缀。

Hosts = ceil((Users × (1 + Devices/User) + Infrastructure) × (1 + Growth))

结果包含什么

结果给出所需VLAN数量、建议前缀、每VLAN可用地址、总容量、利用率、剩余余量和建议VLAN ID范围。它不会分配具体网络地址，也不能替代IP地址管理方案。

办公网与园区网规划示例

规划企业办公室、学校或分支网络时，应统计有线终端、无线终端、电话、打印机、AP、摄像头和管理接口。存在安全或运维边界时应拆分VLAN，不要只因为地址够用就把所有设备放进一个大型广播域。

扩容与工程边界

扩容比例应依据设计周期、人员增长、设备更新和物联网部署计划。上线前还要预留网关与DHCP地址，核对交换机和防火墙容量、广播行为，并为未来VLAN及路由汇总保留连续地址空间。

标准与工程依据

私有IPv4地址空间

RFC 1918定义了企业内部网络常用的私有IPv4地址块。选址时应避免与VPN、云网络及合作方路由重叠。

CIDR与前缀规划

RFC 4632说明CIDR寻址与路由汇总。RFC 3021允许/31专用于点到点链路，并不适用于本规划器采用的多接入终端模型。

常见问题

一个VLAN放多少台主机合适？

没有适用于所有网络的固定上限。应综合广播域范围、故障隔离、安全策略、网关容量和运维复杂度设定目标，并用实测流量与设备规格复核。

IP地址扩容余量应该预留多少？

应根据规划周期、人员增长、终端更新和物联网部署预测确定。百分比只是初步模型，并非固定标准；实际利用率或业务假设变化后应重新计算。

这个工具会分配具体的IP子网地址吗？

不会。工具估算VLAN数量、前缀长度和容量；具体地址仍需在IP地址管理方案中分配不重叠的CIDR网段，并为路由汇总和未来VLAN预留空间。

用户VLAN可以使用/31子网吗？

不可以。RFC 3021规定/31用于点到点链路。本工具采用常规多接入IPv4子网模型，保留网络地址和广播地址。

计算结果能直接作为最终网络设计吗？

不能。结果用于初步容量规划，最终设计还要核对DHCP保留、网关冗余、安全分区、广播行为、硬件容量、路由汇总和现场规范。

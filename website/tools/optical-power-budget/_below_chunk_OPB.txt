<summary class="fb-fold-sum"><span class="fb-fold-title">About &amp; applicability</span></summary>
<div class="fb-fold-body about-card about-card-inline">
<p>Free planning calculator for telecom and network engineers. Runs entirely in the browser: enter OLT/ONU power windows and ODN losses to estimate class budget remaining, receive power, sensitivity margin, overload margin and maximum reach. Application category: engineering utility / optical link design. No account required.</p>
<p>Use for GPON/EPON ODN planning, receive-window checks and troubleshooting. Results are planning aids \u2014 not a substitute for datasheet values, power-meter or OTDR acceptance, or enterprise standards.</p>

<details class="fb-fold blk" id="methodology">
<summary class="fb-fold-sum"><span class="fb-fold-title">How it\u2019s calculated \xb7 methods &amp; formulas</span></summary>
<div class="fb-fold-body">
<div class="eq">class budget = Tx_min \u2212 Rx_sensitivity \u2212 path_penalty<br>
physical loss = fiber + splices + connectors + splitters + other<br>
design loss = physical loss + engineering margin<br>
remaining = class budget \u2212 design loss<br>
Rx = Tx_min \u2212 physical loss</div>
<p>Optical path penalty and engineering margin are budget terms, not present physical component losses, so receive power uses physical loss only. Distinguishing theoretical class budget, physical ODN loss and engineering margin is required for correct Pass / Marginal / Fail interpretation.</p>

<div class="method-defs">
<article><h3>Standard ODN budget</h3><p>Minimum transmit power minus receiver sensitivity minus optical path penalty. GPON B+ allows up to 28 dB ODN loss, while C+ allows up to 32 dB (ITU-T G.984.2 class ranges used as planning references).</p></article>
<article><h3>Physical ODN loss</h3><p>Fiber loss + splice loss + connector loss + multi-stage splitter loss + other passive loss (WDM, attenuators, patch panels).</p></article>
<article><h3>Total design ODN loss</h3><p>Physical ODN loss + engineering margin. The margin covers ageing, temperature, maintenance connections and measurement variation.</p></article>
<article><h3>Estimated receive power</h3><p>Minimum transmit power minus physical ODN loss. Optical path penalty and engineering margin are budget terms, not present physical component losses.</p></article>
<article><h3>Default standards example</h3><p>GPON C+ downstream reference: +3 dBm minimum transmit power, \u221230 dBm ONU sensitivity, \u22128 dBm overload and 1 dB optical path penalty; 10 km at 1490 nm, primary 1:8 plus secondary 1:8, 6 splices, 4 connectors and 3 dB engineering margin.</p></article>
</div>
<p>ITU-T defines system optical classes and ODN loss ranges. For XGS-PON (ITU-T G.9807.1), enter transmit power, receiver sensitivity, overload threshold and optical penalty from the deployed equipment; this tool has no XGS preset and must not infer XGS values from GPON B+/C+. Splice, connector and fiber attenuation assumptions must still be adjusted to enterprise rules, component specifications and field data.</p>
</div>
</details>

<details class="fb-fold blk" id="status-rules">
<summary class="fb-fold-sum"><span class="fb-fold-title">Status rules \xb7 Pass / Marginal / Fail</span></summary>
<div class="fb-fold-body">
<p>The verdict takes the tightest of three checks: remaining class budget, margin above receiver sensitivity, and margin below overload (using maximum transmit power).</p>
<div class="legend">
<div class="lg-p"><b>Pass</b>All three \u2265 3 dB</div>
<div class="lg-m"><b>Marginal</b>Any check 0 \u2264 x &lt; 3 dB</div>
<div class="lg-f"><b>Fail</b>Any check below 0 dB</div>
</div>
<p>The 3 dB Pass / Marginal boundary is this tool\u2019s planning threshold, not a universal standards mandate.</p>
</div>
</details>

<details class="fb-fold blk" id="component-check">
<summary class="fb-fold-sum"><span class="fb-fold-title">Component check \xb7 default loss breakdown</span></summary>
<div class="fb-fold-body">
<p>Physical ODN loss = fiber attenuation \xd7 length + splitter loss + connector loss + splice loss + other passive loss. For the default case: 3.0 dB fiber + 21.0 dB splitters + 1.2 dB connectors + 0.6 dB splices = 25.8 dB physical ODN loss, and the 3 dB engineering margin brings design loss to 28.8 dB. The 1 dB optical path penalty is not added to the loss; it is deducted from the budget: +3 dBm \u2212 (\u221230 dBm) \u2212 1 dB = 32 dB standard ODN budget, leaving 3.2 dB remaining (90% of the budget used). The +3 dBm minimum transmit power therefore predicts \u221222.8 dBm receive power, 7.2 dB above sensitivity; at the +7 dBm maximum transmit power the receiver stays 10.8 dB below the \u22128 dBm overload threshold. The engineering margin is not deducted from receive power.</p>
<p>GPON B+ (28 dB) and C+ (32 dB) labels are reference classes from the selected standards profile, not a guarantee for every OLT/ONU pair. Confirm the actual transmitter, receiver sensitivity, overload, wavelength and ODN class in the equipment datasheet. Continue to <a href="../fiber-loss/">fiber loss</a> for route accounting or the <a href="../../topics/pon-optical/">PON &amp; Optical topic hub</a> for the design workflow.</p>

<div class="blk faq" id="faq">
<span class="eyebrow">FAQ</span>
<h2>Frequently asked questions</h2>
<details><summary>Why does the default change to GPON C+ when 1:8 \xd7 1:8 is retained?</summary>
<p>A 1:8 \xd7 1:8 cascade contributes about 21 dB of splitter loss. With 10 km of fiber, connectors and splices, physical ODN loss is 25.8 dB; adding the 3 dB engineering margin gives a design ODN loss of 28.8 dB. That is above the 28 dB B+ limit but within the 32 dB C+ budget (33 dB transmit-to-sensitivity window minus the 1 dB optical path penalty), leaving 3.2 dB.</p></details>
<details><summary>How does a power budget differ from fiber loss?</summary>
<p>Fiber loss measures route and component losses. A power budget also combines transmit power, receiver sensitivity and overload limits to determine whether equipment can operate reliably.</p></details>
<details><summary>Why use minimum transmit power?</summary>
<p>Designs are checked under worst-case conditions to avoid an optimistic result caused by equipment variation, ageing and temperature.</p></details>
<details><summary>Is higher receive power always better?</summary>
<p>No. Low power can fall below sensitivity, while excessive power can exceed the overload limit. Receive power should remain inside the allowed window.</p></details>

STP Path Cost Explained: Reference Table, Root Path Cost and Calculation

Root path cost is the sum of the STP port costs from a bridge toward the root bridge. Long and short are calculation modes. They are not another name for RSTP and STP. The tables below name the standard and the mode, and the topology uses the same numbers the calculator returns.

An STP cost calculation answers which candidate path a bridge will use to reach the root. The port cost is the cost of one port. The root path cost is the running total of those port costs. A faster link has a lower cost, so the lowest total wins, not the fewest hops.

Port cost and root path cost

IEEE 802.1D-2004 says every bridge has a root path cost. The root bridge is zero. Every other bridge uses the sum of the port path costs on the least-cost path to the root. When two ports on the same bridge show the same root path cost, the better port identifier becomes the root port. The calculator adds the costs and stops. It does not store bridge IDs or port IDs.

Count one port cost per hop, on the port that faces the root. Do not add both ends of the same cable. That is how the calculator treats a comma-separated list: one speed, one cost.

Long and short are not protocol versions

IEEE 802.1D-2004 incorporates two earlier amendments. IEEE 802.1t-2001 supplied the 32-bit long path costs. IEEE 802.1w-2001 supplied RSTP. The 2004 revision also removed the original STP as a conformance option. Putting both amendments in one standard does not make “RSTP” mean “long cost.”

The long mode is a 32-bit port path cost. The short mode is a 16-bit recommended table. A bridge can run Rapid PVST+, which is an RSTP-family mode, and still calculate costs with the short table. Cisco documents that combination as the default on Nexus 9000 NX-OS Release 10.2. Huawei’s S200, S300, S500 and S600 V600R025C10 guide lists MSTP as the default working mode and Dot1t, the IEEE 802.1t long method, as the default path-cost method. Those are two rows in the same default table, not one setting.

Long table: IEEE 802.1D-2004 Table 17-3

Table 17-3 is the long, 32-bit recommendation. Note 3 gives the value for a speed that is not printed in the table: 20,000,000,000 divided by the link speed in kb/s. The range is 1 to 200,000,000 so that 20 hops still fit in the 32-bit root path cost field. The calculator’s long mode rounds that division to the nearest integer and then clamps it to the same range. For every speed in the table below, the division is already an integer, so the displayed STP port cost matches Table 17-3 or the Note 3 formula exactly.

The same standard says a 16-bit bridge that must interwork with 32-bit costs should use 65,535 for a link of 100 kb/s or slower. That exception is not what the calculator’s long mode returns. Long mode stays on the 32-bit formula. Do not copy 65,535 into a long-mode design.

For 10,000 Mbps the arithmetic is 20,000,000,000 ÷ 10,000,000 = 2,000. For 1,000 Mbps it is 20,000,000,000 ÷ 1,000,000 = 20,000. The calculator shows those results with a comma as the thousands separator in every language.

Short table: the calculator’s 16-bit list

The calculator’s short mode accepts only six speeds. This site attributes that list to the 16-bit recommendations in IEEE 802.1D-1998, clause 8.10.2, Table 8-5. It is a different table from Table 17-3. A speed that is not in the list, including 25 Gbps and faster, is rejected. The calculator does not invent a short cost for it.

What the vendors actually default to

Read the path-cost method on the platform you are comparing. Do not transfer one product’s default to another, and do not infer it from the protocol name.

  • Cisco Nexus 9000 NX-OS Release 10.2, Rapid PVST+: the default path-cost method is short, while the spanning-tree mode itself is Rapid PVST+. The published long column matches the calculator from 10 Mb/s through 400 Gb/s. The published short column matches through 10 Gb/s, then uses 1 for 40, 100 and 400 Gb/s. The calculator will not produce that 1. In short mode those speeds are an error.
  • Huawei S200, S300, S500 and S600 V600R025C10: Table 6-16 sets the path-cost method to Dot1t, which is IEEE 802.1t, and sets the working mode to MSTP. The command that selects the standard is separate from the command that selects STP, RSTP or MSTP.

A manual port cost overrides the table on both families. The calculator has no override field. If the switch shows a number that is not in the selected table, record it as a configured cost before you trust the sum.

When the root port is not the one you expected

  1. Record the path-cost method on every bridge, not the protocol name. show spanning-tree pathcost method is the Nexus command. A Rapid PVST+ bridge left on short and a neighbor left on Dot1t disagree on a 1 Gb/s hop by 4 against 20,000.
  2. Record any manual port cost. It replaces the table for that port and changes every root path cost that crosses it.
  3. Write the hop speeds in Mbps and run the calculator in the method the switches actually use. Compare its total with the root path cost on the bridge.
  4. If short mode reports that the speed is undefined, stop. The six-value table has no row. A Nexus short cost of 1 for 40 Gb/s and faster is that platform’s extension, not this calculator.
  5. If the calculator reports a tie, read the bridge ID and the port ID. The page will keep the tie.
  6. IEEE 802.1D-2004 says a link-aggregation member failure does not, by default, change the port path cost. If the displayed root path cost moved after one member failed, look for a configured cost or for a speed the switch is actually using. The calculator uses only the Mbps you type.
  7. After the change, read the root port and the root path cost from the switch again. The page does not see the live topology.

Frequently asked questions

Is RSTP the same as the long STP cost table?

No. RSTP is a protocol. Long and short are path-cost calculation modes. Cisco Nexus 9000 Rapid PVST+ defaults to the short method.

How is root path cost calculated?

It is the sum of the port path costs on the least-cost path to the root bridge. The root bridge itself is zero. The calculator adds one cost for each speed you list.

What does the calculator do when the two totals match?

It reports a tie. It does not compare bridge ID or port ID. Those tie-breakers are read on the switch.

Why does a 25 Gbps link fail in short mode?

The calculator's short table has only 4, 10, 16, 100, 1,000 and 10,000 Mbps. It refuses every other speed instead of copying a vendor value such as 1.

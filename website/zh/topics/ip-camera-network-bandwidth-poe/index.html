建议学习路径

  1. 确定分辨率、编码、帧率和场景复杂度，核对单路峰值码率。
  2. 汇总摄像头流量，分配接入交换机并核验上联与汇聚容量。
  3. 按最大功率与线缆条件核算PoE总预算、端口数和电源冗余。
  4. 按连续录像码率与保留天数规划NVR容量，再核对故障切换。

核心工程校核

带宽与上联
区分平均码率、峰值和协议余量，检查每个故障后路径。PoE供电
复核PSE预算、端口供电等级、设备峰值与线损假设。NVR存储
用连续录像口径估算原始容量，并为系统开销与增长预留空间。

工程边界

码率会随场景复杂度、I帧间隔、VBR设置、音频和厂商实现变化；存储还受录像策略、RAID、文件系统和保留策略影响。N-1结论假设双上联路径独立且单条链路能承载全部摄像头流量；堆叠、MLAG、供电回路及交换机本体故障仍需结合实际拓扑核验。计算器用于初步规划，不替代设备规格、实测流量和验收测试。

常见问题

为什么输入分辨率还要指定编码和帧率？

同一分辨率下，编码效率、帧率、场景运动和细节都会改变码率；计算器提供的是初步估值，应以摄像机峰值配置或实测值校准。

N-1 显示通过就代表系统没有单点故障吗？

不代表。页面只校核模型中的双上联带宽容量；交换机、堆叠控制面、电源、机房链路和NVR故障域需单独验证。

推荐使用顺序

  1. 用计算器比较目标规模并记录假设。
  2. 向摄像机厂商确认峰值码率、最大功率和录像模式。
  3. 按接入交换机分组完成上联、PoE和故障域设计。
  4. 验证NVR可用空间、RAID策略和故障切换实测。

架构示例：分支用户反映备份变慢

示意设计，不是根因诊断或部署配置。

  1. 问题：广域链路是否繁忙，哪些已观测流量有贡献？确定一个出方向接口、业务责任人及统一时间窗口。
  2. 信号：采集可比较的接口计数器/状态，加入已配置流导出以识别贡献者，用日志/通知记录变化。保留导出方、方向、单位、时钟及采集缺口。
  3. 关联：将变慢窗口与利用率、主要已观测贡献者对齐；检查成员分布和错误后再判断总负载能否解释症状。
  4. 响应：由运维定义流程，要求业务佐证、指定链路/业务责任人，并在处理后重复相同业务测试。不预设固定触发阈值。
  5. 保留假设：按批准的隐私、访问和删除策略，为事件复盘与容量趋势保留适当分辨率证据，验证聚合后查询仍有效。
  6. 后续：把兼容的手工观测速率输入应用带宽分析器，再以明确增长假设使用现有预测工具。本专题不采集或计算观测数据。

监控架构总览

为服务问题建立设备、接口和责任团队清单。建议流程为采集、规范化、指标/事件/流量存储、关联及响应，不要求采用某个产品栈。

证据与架构作用

为每条信号保留来源标识、时间戳、方向和单位。把状态/计数器、事件上下文与流量归属关联；单一来源不能完整解释服务。

运行限制与复核

运维检查：纳管前定义缺失数据处理、采集器责任和凭据边界；在实际平台验证协议支持。本专题不部署采集器。

来源 / 策略： S-SNMP S-SYSLOG S-IPFIX S-EDITORIAL

SNMP 轮询

通过请求/响应读取管理对象；GetBulk可读取多项值，对象定义决定含义，适合重复获取状态与计数器。

证据与架构作用

除数值外保留对象标识、响应时间和观测时间；计算接口字节差值前检查计数器不连续信息。

运行限制与复核

按设备能力和业务需要设定间隔与重试预算，不提供通用间隔。采用平台支持的SNMPv3认证/隐私策略并验证配置，不能只看版本标签。

来源 / 策略： S-SNMP S-IF S-SECURITY S-EDITORIAL

SNMP Trap 通知

通知可报告状态变化，无需等待下一次定期读取。SNMPv2 Trap无协议确认，而Inform请求响应，两者通知行为不同。

证据与架构作用

保留发送方、通知对象及接收时间，再核对当前设备/接口状态。通知是已报告事件，不代表连续健康观测。

运行限制与复核

响应建议：测试接收路径和计划故障、去重，并用轮询对账；不能把没有通知直接当作没有变化。

来源 / 策略： S-SNMP S-EDITORIAL

Syslog 日志

用设备事件消息解释状态与配置活动。RFC5424包含严重度、时间戳和结构化数据；消息格式与传输层相互独立。

证据与架构作用

按来源与事件时间关联接口状态或流量变化；保留原消息供调查，并规范化必要字段供检索。

运行限制与复核

运维决策：验证时钟、解析器、传输与敏感日志访问控制。严重度数字本身不能定义服务影响或通知责任人。

来源 / 策略： S-SYSLOG S-EDITORIAL

NetFlow 流记录

通过导出的键与计数器归属流量。NetFlow v9使用模板描述记录结构；本节仅讨论v9，不涵盖全部版本或厂商扩展。

证据与架构作用

比较贡献者前核对导出方、接口/方向、模板与采样元数据，并随报告保留导出配置。

运行限制与复核

运维复核：模板或观测覆盖缺失会影响解析。流记录不是完整抓包，也不能证明应用负载语义。

来源 / 策略： S-NETFLOW S-EDITORIAL

sFlow 采样

sFlow结合报文采样与计数器观测。报文样本用于观察流量构成，计数器样本描述受监控接口，应区分两类证据。

证据与架构作用

保存采样参数、代理和接口标识；把派生流量标为采样估计，并核对其与接口观测的边界。

运行限制与复核

运维限制：没有样本不能证明短流从未存在。应验证硬件与采样配置，不能把样本集当作完整报文历史。

来源 / 策略： S-SFLOW S-EDITORIAL

IPFIX 流信息导出

IPFIX规范导出进程与收集进程间的流信息交换，模板定义字段，观测域限定解释范围。

证据与架构作用

随记录保留导出方/观测域、模板和观测元数据，确认两端实际支持的信息元素。

运行限制与复核

运维检查：判断报告完整性前检查传输、序列、模板与收集器健康；标准化导出并不保证不同平台功能覆盖一致。

来源 / 策略： S-IPFIX S-EDITORIAL

流式遥测

订阅可持续传送指定模型路径。OpenConfig gNMIc文档提供STREAM的sample、on-change及target-defined模式，采样间隔是订阅配置属性。

证据与架构作用

保留目标、路径、时间戳和订阅设置，明确初始状态、后续更新与过期流在看板上的展示。

运行限制与复核

运维验证：核对路径/编码支持，测试重连、采集器背压与缺失更新。流式传送不保证无限频率或通用模型支持。

来源 / 策略： S-GNMI S-EDITORIAL

API 监控

当平台通过认证数据API开放所需状态时可采用。RESTCONF是面向YANG数据的HTTP接口，读取与错误响应具有明确语义。

证据与架构作用

保留端点、模型/版本、HTTP结果与数据新鲜度；区分合法空集、无权限和端点不可用。

运行限制与复核

运维策略：使用支持的只读权限、验证HTTPS身份，按具体API文档处理分页/速率限制。HTTP成功并不自动证明被监控服务正常。

来源 / 策略： S-API S-EDITORIAL

ICMP 与时延

ICMP Echo请求/响应提供IP层响应信号。从固定观测点记录往返观测，它测试该交换而非应用事务。

证据与架构作用

随丢失/往返摘要保存目标、源位置、报文设置与时间戳，事件前后使用相同探测定义比较。

运行限制与复核

运维限制：响应消失时核查探测路径与策略，并用业务检查佐证。仅往返结果不能隔离正向与反向时延。

来源 / 策略： S-ICMP S-EDITORIAL

接口利用率

接口计数器对应特定接口/子层。RFC2863定义高容量字节计数器与不连续信息，应选择可比较的连续观测后再派生速率。

证据与架构作用

算术定义：速率bit/s＝8×字节差÷经过秒数；利用率%＝速率÷已记录容量×100。相减前处理重置/不连续，并保留方向及真实间隔。

运行限制与复核

运维复核：总负载之外查看错误/丢弃及成员分布。长平均可能掩盖短变化，容量与计量层必须匹配。本专题不定义通用安全利用率。

来源 / 策略： S-IF S-EDITORIAL

CPU 与内存

按对象定义解释资源数值。HOST-RESOURCES-MIB规定处理器负载的观测区间，以及存储条目的类型、分配单位、总量和已用量。

证据与架构作用

随序列记录对象/厂商模型和时间窗口。计算已用百分比前区分内存池与存储类型，避免比较不同分母。

运行限制与复核

运维响应：关联路由变化、配置活动及采集缺口，再按平台流程诊断。不能推定通用故障百分比，也不能假设所有设备实现该MIB。

来源 / 策略： S-HOST S-EDITORIAL

光功率监控

读取光学值时保留单位、缩放、状态和新鲜度。Cisco ASR900 DOM文档是厂商/平台特定示例，提供收发光功率等参数及预警/告警表。

证据与架构作用

在可用时记录模块型号、端口/通道、受支持传感器及两端值。通过传感器标识和更新时间区分无法获取与实际低读数。

运行限制与复核

运维复核：使用实际模块/平台规格与校准上下文，关联错误和链路状态。不能跨模块套用固定dBm阈值；应核对DOM支持及所引平台文档限制。

来源 / 策略： S-SENSOR S-OPTICS S-EDITORIAL

告警设计

区分事件到达与可行动告警生命周期。RFC8632按资源/类型识别告警，并区分状态/严重度与人员管理；消息送达不等于响应闭环。

证据与架构作用

建议流程字段：资源、业务影响证据、责任人、佐证信号、确认、恢复检查及升级路径。维护抑制须可追溯，区分无数据与恢复。

运行限制与复核

运维策略：根据业务目标与观测基线选择阈值、持续时间和迟滞，测试触发及恢复。本专题不提供固定通知阈值或自动严重度评分。

来源 / 策略： S-ALARM S-EDITORIAL

监控数据保留

保留期限属于运维及数据治理决策，不是协议统一规定。选存储层前先区分哪些问题需要原始事件/流记录，哪些可使用聚合趋势。

证据与架构作用

建议台账：数据集、责任人、分辨率、访问组、调查/增长时间范围、删除规则及恢复测试。随记录保留导出/模型上下文，避免无必要存储标识。

运行限制与复核

运维权衡：聚合会改变后续可回答的问题，应记录变换并验证代表性查询。按事件复盘、容量规划、隐私要求及实际预算选择期限，不规定固定天数。

来源 / 策略： S-EDITORIAL S-IPFIX S-SYSLOG

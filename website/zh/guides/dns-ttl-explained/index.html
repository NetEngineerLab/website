DNS TTL 是一组资源记录的生存时间。DNS 报文里的单位是秒。TTL calculator 或 DNS TTL calculator 做的是单位换算，再加上你另行输入的缓存时间。换算本身可以精确复核。修改后的记录何时被看见，则不能从秒数直接得到。

秒数在计什么

RFC 1035 把 TTL 定义为以秒计的 32 位无符号整数。值为 0 表示该响应不能在当前事务之后继续缓存。这个定义没有说 300 秒、600 秒或 86400 秒会让每台解析器同时刷新。

TTL 换成分钟，以及分钟换回秒

TTL to minutes 是秒数除以 60。TTL to seconds 是分钟数乘以 60，或小时数乘以 3600。下面五行都是整数，不需要四舍五入。

秒除以 60（分钟）除以 3600（小时）乘回秒
30051/125 x 60 = 300
600101/610 x 60 = 600
360060160 x 60 = 3600
144002404240 x 60 = 14400
864001440241440 x 60 = 86400

300、600、3600、14400 和 86400 秒

300 TTL in minutes 是 300 / 60 = 5 分钟，即 1/12 小时。600 TTL in minutes 是 600 / 60 = 10 分钟，即 1/6 小时。3600 / 60 = 60 分钟 = 1 小时。14400 / 60 = 240 分钟 = 4 小时。86400 TTL in minutes 是 86400 / 60 = 1440 分钟 = 24 小时。反向核对是最后一列：5 x 60 = 300，10 x 60 = 600，60 x 60 = 3600，240 x 60 = 14400，1440 x 60 = 86400。

变更前或希望记录少变时，运维人员会填这些数。它们是算术例子，不是 RFC 1035 规定的传播时间，也不是建议的统一刷新周期。

一台缓存不是整张网络

剩余 TTL 只属于保存了该答案的那台解析器。下面只是例子：权威侧 A 记录的 TTL 为 3600 秒，三台解析器的情况不同。

  1. 解析器 A 在 600 秒前缓存。剩余 TTL = 3600 - 600 = 3000 秒 = 50 分钟。
  2. 解析器 B 刚刚缓存。剩余 TTL = 3600 - 0 = 3600 秒 = 60 分钟。
  3. 解析器 C 仍保存旧答案。它缓存时 TTL 是 86400 秒，并且已经过去 3600 秒。剩余 TTL = 86400 - 3600 = 82800 秒 = 23 小时。

这三台时钟不是同一个传播时间。已经缓存旧记录集的解析器仍受旧 TTL 约束。同一名称下的另一条记录，例如 A 记录为 300 秒而 MX 记录为 3600 秒，按各自的 TTL 到期。

否定缓存是另一只计时器。RFC 2308 把 NXDOMAIN 或 NODATA 应答的 TTL 取为 SOA MINIMUM 字段和 SOA 记录自身 TTL 中较小的一个。若某区的 SOA 记录 TTL 为 600 秒、MINIMUM 为 3600 秒，否定应答使用 600 秒，也就是 10 分钟。区里的 SOA 字段不同，结果就不同。这 10 分钟不适用于正向 A 记录，也不是每个区的固定间隔。

修改记录不等于把 TTL 等完

在权威服务器发布新答案，不会改写递归缓存。每台缓存保留自己保存的记录集，直到该条目的剩余 TTL 降到 0，除非该解析器自己的策略另有处理。有的解析器会限制所保存的 TTL。RFC 8767 允许解析器在无法向权威服务器刷新时继续提供过期答案。委派变更、DNSSEC 校验以及客户端或应用缓存，也会改变用户看见新数据的时间。

变更前降低 TTL，只影响在权威侧已经能看到新 TTL 之后才缓存该记录的解析器。已经按更长的旧 TTL 缓存的条目，会把那个更长的值用到自己的剩余时间结束。不能把“TTL 到期”读成“全网已经同步”。

DNS TTL 计算器根据当前 TTL、缓存已存在时间、否定缓存 TTL 和你输入的权威更新延迟估算规划窗口。这个窗口只对这一组输入是启发式结果，不是测得的全球切换时间。本指南不再另写一条公式。

公开来源：RFC 1035 RFC 2308 RFC 8767 RFC 9199。本页只使用这些文档中可复核的定义，不把任何秒数写成全网同步时间。

常见问题

DNS TTL 是什么？

RFC 1035 把资源记录 TTL 定义为以秒计的 32 位整数。它限制某一台解析器可以重复使用自己已保存的那组记录多久，不是全网同步时钟。

300 秒的 DNS TTL 是多少分钟？

300 除以 60 等于 5 分钟。同样，600 秒是 10 分钟，3600 秒是 60 分钟，14400 秒是 240 分钟，86400 秒是 1440 分钟。

怎样把以分钟表示的 TTL 换回秒？

用分钟数乘以 60。5 分钟是 300 秒，10 分钟是 600 秒，60 分钟是 3600 秒，240 分钟是 14400 秒，1440 分钟是 86400 秒。

TTL 到期是不是表示每台解析器都已经换成新记录？

不是。每台递归缓存只计算自己的剩余 TTL。仍保存旧的 86400 秒答案的解析器，可以在另一台只缓存了 300 秒答案的解析器过期之后继续返回旧数据。RFC 8767 还允许刷新失败时返回过期数据。

剩余 TTL 和旧 TTL 是同一个数吗？

只有刚写入的缓存项才相等。剩余 TTL 等于该缓存项保存的 TTL 减去这台解析器上已经过去的时间。同一名称下的 MX 记录和 A 记录各自有 TTL。

否定缓存会使用地址记录的 TTL 吗？

默认不会。RFC 2308 取 SOA MINIMUM 字段和 SOA 记录自身 TTL 中较小的一个，作为否定应答的 TTL。这两个值要从所查询的区读取，不是正向 A 记录的 TTL。
